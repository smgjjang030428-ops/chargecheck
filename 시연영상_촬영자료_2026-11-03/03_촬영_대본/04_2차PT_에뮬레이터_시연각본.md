# 2차 PT 에뮬레이터 시연 각본

정리일: 2026-11-03 · 2026-11-03 Pleos Connect 에뮬레이터(API 34)에서 아래 순서를 실제로 돌려 확인함

2차 PT는 실차 없이 에뮬레이터로 시연한다. 배포 서버의 실제 데이터는 그날 바뀔 수 있으므로, **실데이터 복사본 + 시연 기록을 넣은 로컬 서버**로 장면을 고정한다. 배포 서버에는 가짜 기록을 넣지 않는다.

## 준비 (발표 30분 전)

PC에서 `chargecheck/server` 폴더:

```powershell
copy chargecheck_real.db chargecheck_pt.db
set DATABASE_URL=sqlite:///./chargecheck_pt.db& set SYNC_ENABLED=false& .venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

다른 창에서:

```powershell
.venv\Scripts\python -m app.jobs.pt_demo_seed
```

마지막 줄이 `시연 준비 완료`여야 한다. 실패 기록은 6시간 뒤 노랑으로 내려가므로 발표 직전에 한 번 더 실행해도 된다(실행마다 새 기기 ID).

| 충전소 | 판정 | 대안 |
|---|---|---|
| 경기성남 SW드림타운 1·2·3 (판교, 차 바로 옆) | 빨강 · 사용 가능 표시인데 실패 제보 | 경기기업성장센터 (초록, 35분 전 충전) |
| 아이온빌딩 (강남) | 빨강 · 운영사 점검·운영 중지 | 아이온커뮤니케이션즈 (같은 건물, 초록) |

에뮬레이터:

1. `01_APK/ChargeCheck_real_debug_로컬서버용.apk` 설치(로컬 서버 `10.0.2.2:8000` 접속). release와 같은 패키지라 release가 있으면 먼저 지운다: `adb uninstall com.chargecheck.app`
2. 기본 내비를 한 번 연다(내비가 준비돼야 목적지를 읽는다). 차 위치는 판교(37.39, 127.13).
3. 차지체크를 열고 시작·권한 허용 → 첫 화면에 판교 충전소와 "주변의 최근 확인 기록"이 보이면 준비 끝.

## 장면 1 — 내비가 고른 충전소를 경유지에서 바꾸기 (약 1분)

1. 차지체크 개발 버튼 [목적지 바꾸기] → 기본 내비가 서울특별시청으로 안내 시작. (또는 내비에서 직접 서울시청 검색)
2. 내비 하단 검색(돋보기) → [충전소] → 목록 1번 **SW드림타운 3 전기차충전소** → [경유지로].
   - 내비 화면에는 "신뢰도 높음 · 1대 중 1대 사용 가능"이 보인다. → **"내비는 사용 가능이라고 하지만"**
3. 몇 초 안에 내비 위 카드: **"사용 가능 표시와 다른 실패 제보가 있어요"** · 대안 경기기업성장센터 · 차량 SOC로 충전 확인.
4. [대안으로 바꾸기] → "경기기업성장센터(으)로 바뀌었어요". 경유지만 바뀌고 목적지 서울특별시청은 그대로(로그 `경유지 교체 요청: 경기기업성장센터 → 서울특별시청`).

설명 포인트: 내비의 '사용 가능'은 운영사 표시값이고, 차지체크는 다른 차들이 실제로 충전에 실패한 기록을 근거로 경고한다. 내비가 이름을 다르게 붙여도("SW드림타운 3 전기차충전소") 낱말·번호로 같은 충전소를 찾는다.

## 장면 2 — 목적지 자체가 운영 중지 (약 40초)

1. 내비 [안내 종료] → 검색 → 최근 목록 **아이온빌딩** → 안내 시작.
2. 카드: **"가는 충전소가 운영 중지예요"** · 아이온빌딩 · 운영사 점검·운영 중지 → 아이온커뮤니케이션즈.
3. [대안으로 바꾸기] → 목적지가 같은 건물의 아이온커뮤니케이션즈로 바뀌고 "바뀌었어요".

설명 포인트: 운영사 점검 정보(공공 데이터)와 차량 실패 제보는 다른 근거라 카드 제목이 다르다. 대안은 차 주변이 아니라 **가려던 충전소 주변**에서 찾는다.

## 장면 3 — 충전 성공·실패 기록 (Virtual Console)

로컬 서버를 쓰는 realDebug에서만 한다(배포 서버에 기록이 올라가지 않게).

1. 차지체크 개발 버튼 [도착 처리] 또는 내비로 충전소 도착.
2. Virtual Console **Energy > Battery SOC**를 1% 이상 올린다 → "정상 1건 남겼어요".
3. 실패: 도착 후 SOC를 그대로 두면 realDebug 기준 급속 2분·완속 3분 뒤(실제 빌드는 급속 10분) "충전이 안 되나요?" → [응, 안 돼요] → 실패 기록 → "몇 번 충전기였나요?". 시간이 부족하면 demo 앱(`ChargeCheck_demo_debug.apk`) 시나리오 ×30으로 보여 주고 "가짜 차량 데이터"라고 말한다.
4. **Motion > Gear Selection** D → P: 출발할 때 보류한 실패 확인을 다음 주차 때 묻는 정책을 보여 줄 수 있다.

## 장면 4 — 시동을 껐다 켜도 이어서 판정 (RETRO, 선택)

에뮬레이터 재부팅 = 시동 끔·켬. 2026-11-03 확인.
1. 판교 SW드림타운 옆(차 위치)에서 Virtual Console **Charge Port → Open** → "충전 시작 지켜보는 중"·"도착 스냅샷 저장".
2. `adb reboot`(2분 넘게 지난 뒤). Virtual Console은 재부팅 때 잔량을 100%로 되돌린다 → 스냅샷이 100% 미만이면 정상(RETRO), 100%였으면 "아까 ○○에서 충전이 안 됐나요?"(실패 RETRO).
3. 부팅 뒤 앱을 열지 않아도 서비스가 켜져 판정한다. 충전소가 차에서 150m 밖이면(개발 버튼 [도착 처리]로 먼 곳에 도착시킨 경우) 기록 없이 끝난다.

## 주의
- Virtual Console을 명령으로 움직일 때: `adb forward tcp:18088 tcp:8088` 후 1초마다 `POST /browser/session?client=...`를 보내야 입력이 먹는다(`PUT /vehicle/gear?gear=Park`, `PUT /vehicle/ev-battery?field=soc&value=43`, `field=charge_port_open&value=true`).
- 정상 기록 뒤에는 차가 150m 떠나야 세션이 끝난다. 에뮬레이터는 차가 움직이지 않으므로 다음 장면 전에 앱을 다시 실행한다.

- 최근 목록 순서는 바뀐다(방금 간 곳이 맨 위). 이름을 보고 누른다.
- 에뮬레이터 내비는 지도 타일을 그리지 않아 배경이 비어 보인다. 정상이다.
- 처음 켤 때 내비가 "navi not ready"면 내비 앱을 한 번 열고 다시 시도한다.
- 경고는 같은 경로에서 한 번만 뜬다. 다시 보여 주려면 [안내 종료] 후 다시 설정한다.
