# 장면별 촬영 방법

## 설치

Pleos Connect 에뮬레이터를 실행하고, 필요한 APK를 창에 끌어다 놓아 설치합니다.

ADB를 쓴다면 이 촬영자료 폴더에서 실행합니다.

```powershell
adb install -r .\01_APK\ChargeCheck_real_release.apk
adb install -r .\01_APK\ChargeCheck_demo_debug.apk
```

두 앱은 함께 설치할 수 있습니다. 실제 앱 패키지는 `com.chargecheck.app`, 시연 앱은 `com.chargecheck.app.demo`입니다. 설치 시 서명 충돌이 발생하면 사용 중인 기존 앱의 서명과 호환되는 APK인지 먼저 확인합니다.

## A. 최신 첫 화면과 지도 — real release

1. 에뮬레이터의 기본 내비를 먼저 실행합니다. 위치 정보가 수신되는지 확인합니다.
2. 실제 차지체크를 실행하고 필요한 동의·권한 절차를 진행합니다.
3. 충전소 목록이 로딩된 뒤 상황카드와 지도를 5~8초 촬영합니다.
4. 숫자로 묶인 핀을 눌러 확대하고, 충전소 하나를 선택해 상세 카드를 촬영합니다.
5. 운영사 정보와 차량 확인 근거가 다른 표현으로 표시되는 장면을 잡습니다.

배포 서버의 데이터와 상태는 촬영 시점에 따라 달라집니다. 특정 충전소가 계속 주의 상태일 것이라고 가정하지 않습니다.

## B. 자동 정상 기록 — demo

1. 화면 왼쪽 위에 “시연 모드 · 가짜 차량 데이터”가 표시된 앱을 엽니다.
2. 배속을 ×120으로 고른 뒤 첫 번째 “LIVE 정상” 시나리오를 누릅니다.
3. 도착 확인 → 배터리 상승 → 정상 기록 문구를 녹화합니다.
4. 앱 내부 대기를 편집해 도착·상승·기록 순간을 이어 붙입니다. 자막은 “시연 데이터 · 시간 압축”을 씁니다.

## C. 실패 확인 후 기록 — demo

1. ×30을 고른 뒤 두 번째 “LIVE 고장” 시나리오를 누릅니다.
2. SOC가 그대로인 상태와 “충전이 안 되나요?” 질문을 촬영합니다.
3. 질문이 보이면 직접 [응, 안 돼요]를 누르고 실패 기록을 촬영합니다.
4. 현재 시연 시나리오는 응답 시점에 도달하면 자동으로 YES를 재생할 수 있습니다. 현재 실제 앱이 무응답을 실패 처리하는 동작과 혼동하지 않도록 직접 답하는 장면을 확보합니다.

시나리오의 “고장”은 기존 메뉴 이름입니다. 내레이션과 자막에서는 실제 근거에 맞게 “충전 실패”라고 설명합니다.

## D. 경고·대안 변경 — demo로 반복 촬영

1. ×30을 먼저 고르고 마지막 “도착 전 경고” 시나리오를 누릅니다.
2. 즉시 뜨는 실패 제보·대안 카드의 제목·근거·대안을 촬영합니다.
3. [대안으로 바꾸기]를 직접 눌러 변경 이후 상태를 촬영합니다.
4. 이 시나리오는 가상 시각 4분에 SWITCH 응답을 자동 재생합니다. ×30이면 경고가 뜬 뒤 약 8초 안에 직접 조작합니다.
5. 내비가 가짜 포트로 동작하는 시나리오이므로 “실제 내비 연동”이라는 자막을 붙이지 않습니다.

## E. 실제 Pleos 내비 교체 — 새로 녹화

1. 실제 release 또는 로컬 서버를 연결한 realDebug를 사용합니다.
2. 실제 주의 정보가 있거나 로컬 시연 데이터로 주의 상태를 준비한 충전소를 목적지 또는 경유지로 설정합니다.
3. 기본 내비 위에 표시되는 경고를 촬영하고, 버튼을 누릅니다.
4. 현재 목적지/경유지가 대안으로 바뀌었는지 기본 내비에서 확인해 촬영합니다.
5. 경유지 교체 시 원래 목적지와 다른 경유지가 유지되는 모습을 함께 잡으면 기능을 설명하기 좋습니다.

로컬 시연 데이터는 개발 서버에서만 준비합니다. 배포 서버에 가짜 충전 기록을 넣어 촬영 장면을 만들지 않습니다. 로컬 서버 실행 방법은 `05_참고_문서/03_앱_실행과_검증.md`를 참고합니다.

## F. 출발 시 보류와 다음 주차 확인

실제 앱의 현재 정책은 출발 시 질문을 숨기고, 다음 주차 때 한 번 묻는 것입니다. 과거 캡처의 “출발 직후 확인 카드”는 최신 동작의 증거로 사용하지 않습니다.

이 기능을 영상에 넣으려면 realDebug·격리된 로컬 서버와 Virtual Console로 충전 시도, 잔량 유지, P→D→P 순서를 재현해 촬영합니다. demo는 주차 신호 없는 기존 표시 방식을 유지하므로 이 정책의 검증 화면으로 쓰지 않습니다.
